The Sakila Database

Our practice playground for the rest of the course.

Sakila is a public sample database from MySQL that models a chain of DVD rental stores. We'll use it for every example from this lecture onwards because it has realistic data: 1000 films, 600 customers, 16,044 rentals, and 16,049 payments, spread across two stores.

The full schema, 16 tables grouped by purpose

🎬 Film catalog

  • film, the movies (title, length, rating, rental_rate, ...)
  • actor, the people who appear in films
  • film_actor, links actors to films (many-to-many)
  • category, genres like Action, Comedy, Drama
  • film_category, links films to categories
  • language, languages a film is available in

👤 Customers and places

  • customer, registered renters
  • address, street-level details
  • city, city names linked to countries
  • country, country names

🏬 Stores and staff

  • store, physical store locations
  • staff, employees at each store

💳 Transactions

  • inventory, individual DVD copies per store
  • rental, who borrowed which copy, when, and when they returned it
  • payment, what the customer paid for the rental
Tables we'll use most today: language, film, customer, rental, payment. The others appear in later lectures (joins, aggregations, etc.).
To follow along: on the ISRT MySQL server, run USE sakila; once at the start of your session. Every SELECT after that targets the Sakila tables by default.

AS, Renaming Columns in the Output

Use AS to give a column a friendlier name in the result. The underlying table is untouched.

SELECT language_id AS id,
       name        AS language_name,
       last_update AS updated_at
FROM sakila.language;

The result table looks like this

idlanguage_nameupdated_at
1English2006-02-15 05:02:19
2Italian2006-02-15 05:02:19
3Japanese2006-02-15 05:02:19

The keyword AS is optional, but recommended

SELECT language_id id, name language_name FROM language;
-- Same result, but harder to read. Prefer the explicit AS.

Aliases with spaces or special characters

SELECT name AS "Language Name", last_update AS "Last Updated"
FROM language;

Quote the alias when it has spaces. Without quotes, MySQL would think "Language" and "Name" are two separate things.

Computed Columns

The select list isn't limited to plain columns. You can include expressions, math, function calls, and the result has one column for each one.

Math on film prices

SELECT title,
       rental_rate,
       rental_rate * 1.10             AS new_rental_rate,
       replacement_cost - rental_rate AS margin
FROM film;

Even pure literals

SELECT title,
       'Sakila Inc.' AS store,
       2026          AS catalog_year
FROM film;

Every row gets the same literal value. Useful for tagging or combining results from different sources.

Always alias computed columns. Without AS, MySQL gives the column a name like rental_rate * 1.10, which is awkward to use in tools, exports, and reports.

🧠 Quick Check

What does SELECT rental_rate AS price FROM film; do?

Built-in Functions

SQL ships with many ready-made functions. Here are the ones you'll meet most often. We'll use the Sakila tables for concrete examples.

String functions, on customer names

SELECT first_name,
       last_name,
       CONCAT(first_name, ' ', last_name) AS full_name,
       UPPER(first_name)                  AS first_upper,
       LOWER(email)                       AS email_lower,
       LENGTH(last_name)                  AS last_name_length
FROM customer;

Numeric functions, on payment amounts

SELECT payment_id,
       amount,
       ROUND(amount, 0)   AS rounded_amount,
       CEIL(amount)       AS rounded_up,
       FLOOR(amount)      AS rounded_down,
       ABS(amount - 5.00) AS distance_from_5
FROM payment;

Date functions, on rental dates

SELECT rental_id,
       rental_date,
       YEAR(rental_date)  AS rental_year,
       MONTH(rental_date) AS rental_month,
       DAY(rental_date)   AS rental_day
FROM rental;
Many more functions exist. SQL has dozens of built-in functions for strings, numbers, dates, NULL handling, and more. We'll cover the ones you'll meet most often. For the rest, see the MySQL Built-in Functions Reference shared with the class as a take-home cheat sheet.

DISTINCT, Removing Duplicates

Sometimes a query naturally returns repeats. DISTINCT collapses identical rows into one.

Without DISTINCT

SELECT rating FROM film;
rating
PG
G
NC-17
PG
R
PG-13
... (1000 rows total)

With DISTINCT

SELECT DISTINCT rating FROM film;
rating
PG
G
NC-17
PG-13
R

DISTINCT applies to the whole row

SELECT DISTINCT rating, rental_duration FROM film;

This returns each unique combination of rating + rental_duration. Two films with the same rating but different durations stay as two rows.

🧠 Quick Check

SELECT DISTINCT rating, rental_duration FROM film; returns each pair only once. If three films have rating = 'PG' and rental_duration = 5, how many rows appear in the result for that pair?

WHERE, Filtering Rows

Up to now, SELECT returned every row. WHERE restricts it to rows that satisfy a condition.

Basic shape

SELECT title, rating, rental_duration
FROM film
WHERE rating = 'G';

Comparison operators

=
Equal to
!= or <>
Not equal to
<
Less than
>
Greater than
<=
Less than or equal
>=
Greater than or equal

Examples on Sakila

-- Films priced at $4.99 or more to rent
SELECT title, rental_rate FROM film WHERE rental_rate >= 4.99;

-- Films longer than 2 hours
SELECT title, length FROM film WHERE length > 120;

-- Films NOT rated R
SELECT title, rating FROM film WHERE rating <> 'R';

-- Customers created from 2006 onwards
SELECT first_name, last_name, create_date
FROM customer
WHERE create_date >= '2006-01-01';
How to read it: "From the film table, give me title, rating, rental_duration, but only the rows where rating = 'G'."

Combining Conditions: AND, OR, NOT

AND, both conditions must be true

-- Films rated G that can be rented for at least a week
SELECT title, rating, rental_duration
FROM film
WHERE rating = 'G'
  AND   rental_duration >= 7;

OR, either condition is enough

-- Family-friendly films: rated G OR PG
SELECT title, rating
FROM film
WHERE rating = 'G'
   OR  rating = 'PG';

NOT, flips a condition

SELECT title FROM film WHERE NOT (rating = 'R');
-- Same as: WHERE rating != 'R' (or <> 'R')

Use parentheses to control precedence

-- "Films rated G AND with rental_duration >= 7,
--  OR films rated PG-13 AND with rental_duration <= 3"
SELECT title, rating, rental_duration
FROM film
WHERE (rating = 'G'     AND rental_duration >= 7)
   OR  (rating = 'PG-13' AND rental_duration <= 3);
Habit to build: when mixing AND and OR, always use parentheses. AND binds tighter than OR by default, so without parentheses the meaning can be different from what you intended.

Putting It Together, A Worked Query

One realistic Sakila question, broken down piece by piece.

Question: "From the film catalog, list each distinct film title with its rating, length in minutes, and a proposed new rental rate (current rate × 1.10), but only for family-friendly films, rated G or PG, that are at least 90 minutes long."

Step 1, plain SELECT

SELECT title, rating, length, rental_rate
FROM film;

Step 2, computed column with AS

SELECT title,
       rating,
       length             AS duration_minutes,
       rental_rate * 1.10 AS new_rental_rate
FROM film;

Step 3, add filters with WHERE / AND / OR

SELECT DISTINCT
       title,
       rating,
       length             AS duration_minutes,
       rental_rate * 1.10 AS new_rental_rate
FROM film
WHERE (rating = 'G' OR rating = 'PG')
  AND   length >= 90;

That's a real-world query. In Lecture 6, we'll add ORDER BY to sort the result, LIMIT to keep only the top few, and shortcut operators like BETWEEN, IN, and IS NULL to write filters more concisely.

Build queries one piece at a time. Start with SELECT * FROM table;, then narrow columns, then add WHERE one condition at a time, running after each change to see the effect. Mistakes show up early, while the query is small.

Recap, what we covered

  • AS renames columns in the result; quote aliases with spaces.
  • Computed columns let you do math, build strings, or call functions right inside the SELECT list. Always alias them.
  • Common functions: CONCAT, UPPER, LOWER, LENGTH, ROUND, CEIL, FLOOR, ABS, YEAR, MONTH, DAY.
  • DISTINCT collapses duplicate rows; with multiple columns it considers the whole row.
  • WHERE filters rows. Comparison operators: =, != (or <>), <, >, <=, >=.
  • Combine conditions with AND, OR, NOT. Use parentheses when mixing.
