🚀 Challenges: Four Integrative Sakila Reports

Real query-writing rarely uses one clause at a time. Each challenge below asks for a single statement that combines several ingredients at once, WHERE, aliases, computed columns, ORDER BY, LIMIT, and friends like IN, BETWEEN, and LIKE. Challenge 1 walks you there in five small steps; Challenges 2 to 4 ask you to write the whole integrative query in one go.

Challenge 1 · The Scenario

The store manager wants a quick report: the longest family-friendly films in the catalog, with a readable runtime, a computed value-for-money column, and only those whose title hints at a popular theme. You'll build it in five steps so you see each new ingredient on its own.

Tables in play

Only one: film. The columns you'll touch are title, length (in minutes), rating, rental_rate, rental_duration.

1Plain SELECT

Write a SELECT that returns title, length, rating, and rental_rate from the film table. No filter yet, no sort. Just the four columns.

2Add aliases and a computed column

Rename length to minutes. Add a new column hours that is length divided by 60, rounded to 1 decimal place. Rename rental_rate to price_per_rental.

3Filter with IN and BETWEEN

Keep only family-friendly films, where rating is one of 'G', 'PG', or 'PG-13', and the runtime is reasonable: length between 90 and 150 minutes (inclusive).

4Add a title pattern with LIKE

Restrict further to films whose title contains the word LOVE anywhere. (Sakila stores titles in upper case; the default collation is case insensitive but write it in upper case to be safe.)

5Sort and crop the result

Sort the survivors longest first (length DESC), break ties alphabetically by title, and keep only the top 10 rows. That's your finished report.

Compare with the suggested solution

When you've worked through steps 1 to 5, click below to see one possible final query. Yours might differ; what matters is that it returns sensible rows and uses the ingredients correctly.

-- Final report: top 10 longest family-friendly love stories
SELECT title,
       length        AS minutes,
       ROUND(length / 60, 1) AS hours,
       rating,
       rental_rate   AS price_per_rental
FROM film
WHERE rating IN ('G', 'PG', 'PG-13')
  AND length BETWEEN 90 AND 150
  AND title LIKE '%LOVE%'
ORDER BY length DESC, title ASC
LIMIT 10;
Why each piece is there:
  • AS minutes and AS hours give the report column names that read like a human wrote them, not a database engine.
  • ROUND(length / 60, 1) turns 142 minutes into 2.4, easier to scan than raw minutes.
  • IN ('G', 'PG', 'PG-13') is shorter and clearer than three OR clauses.
  • BETWEEN 90 AND 150 is inclusive on both ends, so a 90-minute and a 150-minute film both qualify.
  • LIKE '%LOVE%' matches the word anywhere in the title. With 'LOVE%' it would only match titles that start with LOVE.
  • The two-column ORDER BY sorts ties deterministically, important for paginated reports.
  • LIMIT 10 crops to the top of the sorted list. Without ORDER BY it would just be the first 10 rows the database happens to find, which is rarely what you want.

Challenge 2 · VIP Customer Contact Sheet

Marketing wants a one-shot contact sheet: active customers from stores 1 and 2 whose last name starts with a letter in the first half of the alphabet, with a friendly full name column, sorted by last name, capped at 15 rows.

Tables in play

Only customer: customer_id, store_id, first_name, last_name, email, active.

Write one integrative query

In a single statement against customer, combine all of the following: WHERE active = 1, store_id IN (1, 2), and last_name LIKE 'A%' through 'M%' (hint: last_name < 'N' is one clean way to say "starts with A to M"); a computed full_name column built from first_name and last_name with CONCAT, aliased with AS; sorted with ORDER BY last_name ASC; and cropped with LIMIT 15.

Compare with the suggested solution

Yours might phrase the "A to M" filter differently (some students prefer LIKE chains with OR); either is fine as long as the row set and ordering match.

-- Active customers, stores 1-2, last name starting A-M, sorted, top 15
SELECT customer_id,
       CONCAT(first_name, ' ', last_name) AS full_name,
       email,
       store_id
FROM customer
WHERE active   = 1
  AND store_id IN (1, 2)
  AND last_name < 'N'
ORDER BY last_name ASC
LIMIT 15;
Why each piece is there:
  • active = 1 filters out closed accounts before anything else runs.
  • store_id IN (1, 2) is a short list filter, cleaner than two OR conditions.
  • last_name < 'N' uses the fact that string comparison in SQL is alphabetical, so it grabs every last name from A up to (not including) N without a wildcard scan on every row.
  • CONCAT(...) AS full_name is a computed column: it exists only in the result set, built from two real columns.
  • ORDER BY last_name ASC and LIMIT 15 together give a deterministic, capped contact sheet, exactly what you'd hand to marketing.

Challenge 3 · Mid-Range Rental Value Films

The purchasing team wants films that are reasonably priced to rent, family-friendly or teen-rated, and have a title starting with a specific letter, ranked by how much rental value they pack in per view.

Tables in play

Only film: title, rental_rate, rental_duration, rating.

Write one integrative query

In a single statement against film, combine: rental_rate BETWEEN 2 AND 4; rating IN ('PG', 'PG-13'); title LIKE 'T%'; a computed column total_rental_value equal to rental_rate * rental_duration, aliased with AS; sorted by that computed column descending; and only the top 10 rows.

Compare with the suggested solution

Note that you can ORDER BY a computed column using its alias, MySQL resolves the alias name from the SELECT list.

-- Mid-priced PG/PG-13 films starting with T, ranked by rental value
SELECT title,
       rental_rate,
       rental_duration,
       rating,
       rental_rate * rental_duration AS total_rental_value
FROM film
WHERE rental_rate BETWEEN 2 AND 4
  AND rating IN ('PG', 'PG-13')
  AND title LIKE 'T%'
ORDER BY total_rental_value DESC
LIMIT 10;
Why each piece is there:
  • BETWEEN 2 AND 4 keeps the price band inclusive on both ends.
  • IN ('PG', 'PG-13') replaces two OR conditions on the same column.
  • LIKE 'T%' matches only titles starting with T, no leading wildcard means the pattern anchors to the start of the string.
  • rental_rate * rental_duration AS total_rental_value is a computed column: it doesn't exist in the table, it's built fresh for this report.
  • ORDER BY total_rental_value DESC sorts by the alias, and LIMIT 10 keeps only the top-ranked rows.

Challenge 4 · Recent High-Value Payments Digest

Finance wants a digest of sizeable payments made in a specific month, with a friendlier date column name and an estimated late-fee column, sorted with the biggest payments first.

Tables in play

Only payment: payment_id, amount, payment_date.

Write one integrative query

In a single statement against payment, combine: amount > 5; payment_date BETWEEN '2005-07-01' AND '2005-07-31'; a renamed payment_date column aliased as paid_on; a computed column late_fee_estimate equal to amount * 0.15, aliased with AS; sorted by amount descending; and only the top 20 rows.

Compare with the suggested solution

This is the same shape of query you'll write constantly on the job: filter, compute, rename, sort, cap, all in one pass over the table.

-- Payments over $5 in July 2005, with an estimated late fee, biggest first
SELECT payment_id,
       amount,
       payment_date    AS paid_on,
       amount * 0.15 AS late_fee_estimate
FROM payment
WHERE amount > 5
  AND payment_date BETWEEN '2005-07-01' AND '2005-07-31'
ORDER BY amount DESC
LIMIT 20;
Why each piece is there:
  • amount > 5 filters out the small transactions before anything else is computed.
  • payment_date BETWEEN '2005-07-01' AND '2005-07-31' is inclusive on both ends, so it covers the whole month.
  • payment_date AS paid_on renames a real column purely for readability in the report.
  • amount * 0.15 AS late_fee_estimate is a computed column that exists only in the output.
  • ORDER BY amount DESC plus LIMIT 20 hands finance exactly the top 20 biggest payments in the window, nothing more.
