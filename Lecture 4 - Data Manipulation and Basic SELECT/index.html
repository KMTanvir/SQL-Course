INSERT, Putting Data In

INSERT INTO adds new rows to a table. You name the table, list the columns, then list the values in the same order.

One row at a time

INSERT INTO student (student_id, name, email, major, gpa)
VALUES (101, 'Maya Hassan', 'maya@isrt.ac.bd', 'Statistics', 3.85);

Many rows at once

INSERT INTO student (student_id, name, email, major)
VALUES
  (102, 'Arif Rahman',  'arif@isrt.ac.bd',  'Statistics'),
  (103, 'Priya Das',    'priya@isrt.ac.bd', 'Data Science'),
  (104, 'Tanvir Ahmed', 'tanvir@isrt.ac.bd','Statistics');

Multi-row insert is one trip to the database, much faster than four separate inserts.

Skipping columns: defaults and AUTO_INCREMENT

You don't have to list every column. Skipped ones get their DEFAULT (or NULL if no default), and AUTO_INCREMENT columns are filled in for you.

-- book_id is AUTO_INCREMENT, created_at has DEFAULT CURRENT_TIMESTAMP
INSERT INTO book (title, author) VALUES ('Clean Code', 'Robert Martin');

UPDATE, Changing Existing Rows

UPDATE modifies rows that match a WHERE clause. Without WHERE, it changes every row in the table.

Basic shape

UPDATE student
SET major = 'Data Science'
WHERE student_id = 101;

Updating multiple columns at once

UPDATE student
SET major = 'Data Science',
    gpa   = 3.92
WHERE student_id = 101;

Using expressions, not just literals

-- Give every employee in department 5 a 10% raise
UPDATE employee
SET salary = salary * 1.10
WHERE department_id = 5;
The classic disaster: UPDATE student SET major = 'CS'; with no WHERE clause changes every student's major. Always think: "which rows should this touch?" before pressing run.

DELETE, Removing Rows

DELETE FROM removes rows that match a WHERE clause. Same warning as UPDATE: no WHERE means every row.

-- Remove one specific student
DELETE FROM student WHERE student_id = 101;

-- Remove all rows older than 2020
DELETE FROM log WHERE created_at < '2020-01-01';

-- DANGER: removes EVERY row in the table
DELETE FROM student;
Safe habit: before running a destructive UPDATE or DELETE, run a SELECT with the same WHERE clause to preview the rows you'd touch. Once the preview looks right, swap SELECT for the real verb.

ALTER TABLE, Reshaping a Table

Tables aren't carved in stone. ALTER TABLE lets you add, change, rename, or drop columns and constraints after the table exists.

-- Add a column
ALTER TABLE student ADD phone VARCHAR(20);

-- Change a column's type or constraints
ALTER TABLE student MODIFY phone VARCHAR(25) NOT NULL;

-- Rename a column (MySQL 8+)
ALTER TABLE student RENAME COLUMN phone TO mobile;

-- Drop a column
ALTER TABLE student DROP COLUMN mobile;

-- Add a constraint after the fact
ALTER TABLE student ADD CONSTRAINT uq_email UNIQUE (email);
Be careful with DROP COLUMN. It deletes all the data in that column, no undo.

DROP TABLE vs TRUNCATE TABLE

Two commands that look similar but do very different things. And both are different from DELETE.

DROP TABLE

Deletes the entire table, structure and data. The table is gone, you'd have to CREATE TABLE it again.

DROP TABLE student;

TRUNCATE TABLE

Removes all rows, but keeps the table's columns and constraints. Resets AUTO_INCREMENT back to 1.

TRUNCATE TABLE student;

The full comparison

CommandRemoves dataRemoves tableResets AUTO_INCREMENTCan use WHERE
DELETE FROM t WHERE ...Matched rowsNoNoYes
DELETE FROM t;All rowsNoNoNo
TRUNCATE TABLE t;All rows (fast)NoYesNo
DROP TABLE t;All rowsYes(table is gone)No
None of these have an undo button. In real systems, take a backup before any of them.

SELECT, Reading Rows

SELECT is the workhorse of SQL. Every report, dashboard, and analysis is built on it.

The simplest form

SELECT * FROM student;

Reads as: "give me every column (*) for every row of the student table". Useful for a quick look, but in real work you almost always want specific columns.

Read SELECT inside out: "Take this table, keep these columns, give me the rows." That's it. Everything else, filtering, sorting, grouping, is a refinement we'll add over the next few lectures.

Column Projection, Picking the Columns You Need

Instead of SELECT *, list the columns you actually want, in the order you want them. This is called projection.

-- All columns
SELECT * FROM student;

-- Just two
SELECT name, major FROM student;

-- A specific order, regardless of how the table was created
SELECT major, name, email FROM student;

Why prefer named columns over *

  • Clarity: the reader sees exactly which columns matter.
  • Stability: if someone adds a column to the table later, your query keeps returning the same shape.
Habit to build: use SELECT * while exploring; switch to a named column list before saving the query for real use.

Putting It Together, A Worked Example

One small employee table, exercising what we covered today.

Starting state

CREATE TABLE employee (
  employee_id INT PRIMARY KEY AUTO_INCREMENT,
  name        VARCHAR(100) NOT NULL,
  department  VARCHAR(40),
  salary      DECIMAL(10, 2)
);

1. INSERT some rows

INSERT INTO employee (name, department, salary) VALUES
  ('Maya Hassan',  'Statistics',    68000),
  ('Arif Rahman',  'Statistics',    62000),
  ('Priya Das',    'Data Science',  75000),
  ('Tanvir Ahmed', 'Statistics',    71000);

2. SELECT to look around

SELECT name, department, salary FROM employee;

3. ALTER TABLE to add a column

ALTER TABLE employee ADD joined_at DATE DEFAULT (CURRENT_DATE);

4. UPDATE to change something

-- Statistics raise of 8%
UPDATE employee
SET    salary = salary * 1.08
WHERE  department = 'Statistics';

5. DELETE rows we no longer need

-- Tanvir moves on
DELETE FROM employee WHERE name = 'Tanvir Ahmed';

6. Tear it all down (if you're done experimenting)

-- Empty the table but keep its structure
TRUNCATE TABLE employee;

-- Or remove it completely
DROP TABLE employee;

Recap, What We Covered

  • INSERT adds rows: one row, many rows, or rows produced by another query.
  • Skipping a column on INSERT lets defaults and AUTO_INCREMENT do their work.
  • UPDATE ... SET ... WHERE changes existing rows. WHERE is what saves you from disaster.
  • DELETE FROM ... WHERE removes rows. Without WHERE, all rows go.
  • ALTER TABLE adds, modifies, renames, or drops columns and constraints later.
  • DROP TABLE removes the table entirely; TRUNCATE TABLE empties it but keeps the structure (and resets AUTO_INCREMENT).
  • SELECT col_list FROM table reads rows. SELECT * is for exploring, named columns are for keeping.
  • Column projection means listing the columns you want, in the order you want them.
  • Safe habit: preview destructive UPDATE/DELETE with a SELECT using the same WHERE.
