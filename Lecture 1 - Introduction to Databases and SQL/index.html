What is a Database?

A database is an organized collection of related data, designed so we can efficiently store, search, and update it.

Think of a telephone book. Thousands of names and numbers organized alphabetically so you can quickly look up a contact. A database is the same idea, just electronic, and much more powerful.

Three defining characteristics

  • Organized, data is structured, not random (like the alphabetical phone book).
  • Searchable, you can ask specific questions ("whose number starts with 555?") and get answers fast.
  • Persistent, data survives restarts, crashes, and years of use.

Where do you see them?

Every time you log into a website, check your bank balance, book a ticket, or stream a movie, a database is working behind the scenes.

The Relational Model

In a relational database, data is stored in tables. Each table holds information about one kind of thing, students, orders, products.

Row (record)

One entry in the table, for example, one student named "Maya Hassan".

Column (field)

One attribute across all rows, like "email" or "birth_date".

Example: Student table

student_idnamemajoremail
101Maya HassanStatisticsmaya@isrt.ac.bd
102Arif RahmanApplied Statisticsarif@isrt.ac.bd
103Priya DasData Sciencepriya@isrt.ac.bd

Three rows, four columns. Simple, but the real power comes from connecting tables together. That's what keys are for.

Primary Keys

A primary key is a column (or set of columns) whose values uniquely identify every row in a table.

Rule: No two rows can share the same primary key value. And a primary key value can never be NULL.

Which column should be the primary key?

student_idnamemajor
101Maya HassanStatistics
102Arif RahmanStatistics
103Priya DasData Science

student_id, because it's guaranteed unique. name won't work (two students might share a name), and major definitely won't work (many students share a major).

Compound Keys and Foreign Keys

Compound (composite) key

Sometimes no single column is unique, but a combination of columns is.

Enrollment table: Any one student might appear in many rows (enrolled in many courses). Any one course has many students. But the pair (student_id, course_id) is unique, that's the compound key.

Foreign key

A foreign key is a column whose value references the primary key of another table. That's how we link tables together.

Customer
  • 🔑 customer_id (PK)
  • name
  • email
Order
  • 🔑 order_id (PK)
  • ↗ customer_id (FK)
  • order_date
  • total

Order.customer_id → Customer.customer_id tells us which customer placed each order.

A Brief History of SQL

Understanding where SQL came from helps explain why it looks the way it does.

1970

Edgar F. Codd publishes "A Relational Model of Data for Large Shared Data Banks" at IBM, proposing that data should live in tables you can query with a mathematical language.

1974

IBM's System R project creates a query language called SEQUEL (Structured English Query Language).

Late 1970s

Renamed to SQL (for trademark reasons), pronounced "S-Q-L" or "sequel".

1986

SQL becomes an ANSI standard, then an ISO standard. It's now the common language of almost every relational database.

Today

MySQL, PostgreSQL, Oracle, SQL Server, SQLite, they all speak dialects of the same SQL.

Takeaway: Learn SQL once, and you can work with most databases on Earth.

SQL Command Families: DDL vs DML

SQL commands fall into a few families. The two you'll use every day are DDL and DML.

DDL, Data Definition Language

Changes the structure of the database (tables, columns, constraints).

  • CREATE, make a table
  • ALTER, change a table
  • DROP, remove a table
  • TRUNCATE, empty a table

DML, Data Manipulation Language

Changes the data inside tables (rows).

  • SELECT, read rows
  • INSERT, add rows
  • UPDATE, modify rows
  • DELETE, remove rows
Mnemonic: DDL defines, DML manipulates. Structure vs contents.

Your Very First SQL Commands

Once you're connected to MySQL, these are the first commands you'll run to look around.

See all databases on the server

SHOW DATABASES;

Pick one to work in

USE sakila;

See all tables in that database

SHOW TABLES;

See a table's structure

DESCRIBE film;
Every SQL statement ends with a semicolon ;. The database uses it to know where one command stops and the next begins. Forget it, and the database will patiently wait for the rest.

SQL is case-insensitive (mostly)

SELECT, select, and Select all work. Convention: we write keywords in UPPERCASE to make them stand out from table and column names.

SQL Comments

Comments let you leave notes in your SQL for yourself and your teammates. The database ignores them.

Single-line comment

-- This finds every student in Statistics major
SELECT * FROM student WHERE major = 'Statistics';

Multi-line comment

/*
   Report: top-5 highest-paid employees
   Author: K.M. Tanvir
   Last updated: 2026-04-21
*/
SELECT name, salary FROM employee
ORDER BY salary DESC LIMIT 5;
Why comment? To explain why, not what. The code already says what it does, your comment should explain intent: "we exclude part-time staff here because HR requested it."

Recap, What We Covered

  • A database is organized, searchable, persistent data.
  • Relational databases store data in tables (rows × columns).
  • Primary keys uniquely identify rows. Foreign keys link tables together. Compound keys use multiple columns together.
  • SQL was born at IBM in the 1970s (thanks to Edgar F. Codd) and is now the global standard.
  • MySQL is our tool. All course work runs on the ISRT MySQL server, accessed through MySQL Workbench (or any MySQL client).
  • DDL changes structure (CREATE, ALTER, DROP, TRUNCATE). DML changes data (SELECT, INSERT, UPDATE, DELETE).
  • SHOW DATABASES;, USE ...;, SHOW TABLES;, DESCRIBE ...; are your first "look around" commands.
  • End every statement with ;. Use -- single line or /* multi-line */ for comments.
