ORDER BY, Sorting the Result

Without ORDER BY, the database is free to return rows in any order. If you need a specific order in the output, you have to ask for it.

Basic shape

SELECT title, length
FROM film
ORDER BY title;

Default is ascending (A to Z, smallest to largest, earliest to latest). It is the same as writing ORDER BY title ASC.

Sorts work on any orderable type

  • Strings → alphabetical (with the column's collation rules).
  • Numbers → numerical, smallest first.
  • Dates and datetimes → earliest first.
  • NULLs → MySQL puts them first by default in ASC, last in DESC.
Mental model: SELECT decides which rows and columns. WHERE filters which rows. ORDER BY decides what sequence those rows come back in.

ASC and DESC

Add DESC after the column name to sort in descending order.

-- Most expensive films first
SELECT title, rental_rate
FROM film
ORDER BY rental_rate DESC;

-- Newest customers first (most recent create_date on top)
SELECT first_name, last_name, create_date
FROM customer
ORDER BY create_date DESC;

You can mix ASC and DESC per column

SELECT first_name, last_name
FROM customer
ORDER BY last_name ASC, first_name DESC;

Last name ascending, but within the same last name, first names come back in reverse alphabetical order.

ORDER BY Multiple Columns

List several columns, separated by commas. The database sorts by the first, and only uses later columns to break ties.

-- Customers alphabetized by surname, then first name
SELECT first_name, last_name, email
FROM customer
ORDER BY last_name, first_name;

Sample result

first_namelast_nameemail
JAMIEANDERSONjamie.anderson@sakilacustomer.org
WILLIAMANDERSONwilliam.anderson@sakilacustomer.org
HENRYBAKERhenry.baker@sakilacustomer.org
JOSEBAKERjose.baker@sakilacustomer.org

Each column has its own direction

-- Highest rental_rate first; for ties, alphabetical by title
SELECT title, rental_rate
FROM film
ORDER BY rental_rate DESC, title ASC;
Why a tiebreaker matters: if two rows are equal on the first sort column, MySQL is free to put either one first. A second sort column makes the order predictable from run to run.

Sort by Expression or Alias

The ORDER BY column doesn't have to be a plain column from the table. It can be an expression, a function call, or an alias defined in your SELECT list.

By an expression

-- Sort by total potential rental income
SELECT title, rental_rate, rental_duration
FROM film
ORDER BY rental_rate * rental_duration DESC;

By a function

-- Sort films by the length of their title
SELECT title, LENGTH(title) AS title_len
FROM film
ORDER BY LENGTH(title) DESC;

By an alias from SELECT

SELECT title, rental_rate * 12 AS annual
FROM film
ORDER BY annual DESC;

Aliases in ORDER BY are convenient because you don't repeat the expression.

By column position number, possible but discouraged

SELECT title, rental_rate FROM film ORDER BY 2 DESC;
-- "2" means the 2nd column in the SELECT list (rental_rate). Less readable, avoid.

LIMIT, Capping the Result Size

LIMIT n tells the database to return at most n rows. Useful when you only want to see a sample, or the "top few" of something.

-- Show just the first 5 films found
SELECT film_id, title FROM film LIMIT 5;

LIMIT + ORDER BY = top-N queries

-- Top 5 most expensive films to rent
SELECT title, rental_rate
FROM film
ORDER BY rental_rate DESC
LIMIT 5;

-- 10 longest films in the catalog
SELECT title, length
FROM film
ORDER BY length DESC
LIMIT 10;
LIMIT without ORDER BY is unpredictable. Asking for "5 rows" without specifying an order means you might get any 5 rows, and the result can change run to run. Always pair LIMIT with ORDER BY when the order matters.

LIMIT with OFFSET, Pagination

To "skip" some rows before returning, add an offset. There are two equivalent syntaxes.

-- Form 1: LIMIT count OFFSET skip
SELECT title FROM film ORDER BY title LIMIT 10 OFFSET 20;

-- Form 2: LIMIT skip, count   (older shorthand; means the same thing)
SELECT title FROM film ORDER BY title LIMIT 20, 10;

Both queries skip the first 20 rows and then return the next 10.

Pagination, page by page

Suppose your app shows 10 films per page, ordered alphabetically.

-- Page 1 (rows 1-10)
SELECT title FROM film ORDER BY title LIMIT 10 OFFSET 0;

-- Page 2 (rows 11-20)
SELECT title FROM film ORDER BY title LIMIT 10 OFFSET 10;

-- Page p (rows (p-1)*10 + 1 .. p*10)
-- offset = (p - 1) * page_size
Always pair pagination with ORDER BY. Without a consistent order, the same row can appear on different pages, or disappear entirely between requests.

BETWEEN, A Cleaner Range Filter

BETWEEN a AND b is shorthand for >= a AND <= b. It is inclusive on both ends.

-- These two are equivalent
SELECT title, length FROM film WHERE length BETWEEN 90 AND 120;
SELECT title, length FROM film WHERE length >= 90 AND length <= 120;

Works on numbers, dates, and strings

-- Payments between $5.00 and $7.00
SELECT payment_id, amount
FROM payment
WHERE amount BETWEEN 5.00 AND 7.00;

-- Customers with customer_id between 10 and 50
SELECT customer_id, first_name, last_name
FROM customer
WHERE customer_id BETWEEN 10 AND 50;

-- Rentals during a specific week
SELECT rental_id, rental_date
FROM rental
WHERE rental_date BETWEEN '2005-06-14' AND '2005-06-20';

NOT BETWEEN excludes the range

SELECT title, length FROM film
WHERE length NOT BETWEEN 90 AND 120;
-- Returns films shorter than 90 OR longer than 120 minutes
Watch the inclusive ends. BETWEEN 90 AND 120 matches 90, 120, and everything in between. If you wanted "strictly less than 120", use >= 90 AND < 120 instead.

IN, Match Any Value in a List

IN (val1, val2, ...) is shorthand for "= val1 OR = val2 OR ...". Cleaner and easier to read.

-- Long form with OR
SELECT title, rating FROM film
WHERE rating = 'G'
   OR  rating = 'PG'
   OR  rating = 'PG-13';

-- Same thing, with IN
SELECT title, rating FROM film
WHERE rating IN ('G', 'PG', 'PG-13');

Works for numbers too

-- Films from a few specific languages
SELECT title, language_id
FROM film
WHERE language_id IN (1, 2, 3);

-- Customers belonging to store 1 or 2
SELECT customer_id, first_name, store_id
FROM customer
WHERE store_id IN (1, 2);

NOT IN excludes the list

SELECT title, rating FROM film
WHERE rating NOT IN ('R', 'NC-17');
Watch out for NOT IN with NULLs. If the list contains NULL, NOT IN returns no rows because comparisons with NULL are "unknown". A safe rule: never put NULL in an IN list.

IS NULL and IS NOT NULL

Recall from Lecture 2: NULL means "unknown / not applicable". Comparing it with = always returns "unknown", never true. Use IS NULL or IS NOT NULL to test for NULL.

Sakila context: in the rental table, return_date is NULL while a film is still rented out and gets filled in when the customer returns it. So "rentals not yet returned" is exactly the IS NULL check. 
-- WRONG: returns no rows even when return_date really IS NULL
SELECT rental_id FROM rental WHERE return_date = NULL;

-- Correct: rentals not yet returned
SELECT rental_id, customer_id, rental_date
FROM rental
WHERE return_date IS NULL;

-- Correct: rentals that HAVE been returned
SELECT rental_id, customer_id, rental_date, return_date
FROM rental
WHERE return_date IS NOT NULL;

NULL also affects other operators

LIKE, Pattern Matching

So far we've matched exact values. LIKE matches a pattern, with two wildcards:

% (percent sign)

Matches zero or more characters of any kind.

  • 'A%' matches anything starting with A
  • '%man' matches anything ending with man
  • '%er%' matches anything containing 'er'

_ (underscore)

Matches exactly one character.

  • '_at' matches "cat", "bat", "hat"
  • 'A___' matches any 4-char string starting with A

Sakila examples

-- Customers whose first name starts with 'A'
SELECT first_name, last_name
FROM customer
WHERE first_name LIKE 'A%';

-- Films with titles ending in 'MAN'
SELECT title FROM film WHERE title LIKE '%MAN';

-- Addresses containing 'Street'
SELECT address FROM address WHERE address LIKE '%Street%';
Wildcards only work with LIKE. WHERE first_name = 'A%' looks for the literal value "A%", not names starting with A. Use LIKE when you want pattern matching.

The _ Wildcard, One Character Each

Each underscore matches exactly one character, no more, no less.

-- Customers whose last_name is exactly 5 characters long
SELECT first_name, last_name
FROM customer
WHERE last_name LIKE '_____';

-- Films whose title is 4 characters and starts with 'A'
SELECT title FROM film WHERE title LIKE 'A___';

-- Last names where the second letter is 'A'
SELECT last_name
FROM customer
WHERE last_name LIKE '_A%';

Combining % and _

-- Titles where the third character is 'X', any length after that
SELECT title FROM film WHERE title LIKE '__X%';
PatternMatchesDoesn't match
'a%'"apple", "a", "abc""banana"
'%a'"banana", "data", "a""apple"
'_a'"ba", "ca", "ma""a" (too short), "baa"
'a_'"ab", "az""a", "abc"
'_a%'"bat", "cat", "data""apple" (no leading char before 'a')

NOT LIKE, Case, and Escaping

NOT LIKE excludes the pattern

-- Films whose title does NOT start with 'A'
SELECT title FROM film WHERE title NOT LIKE 'A%';

Case sensitivity

By default, MySQL's LIKE is case-insensitive (assuming the standard collation). So 'A%' matches both "Apple" and "apple".

-- These both match "Apple" and "apple" on the default collation
SELECT first_name FROM customer WHERE first_name LIKE 'a%';
SELECT first_name FROM customer WHERE first_name LIKE 'A%';

If you need strict case-sensitive matching, force binary comparison with BINARY:

SELECT first_name FROM customer WHERE first_name LIKE BINARY 'A%';

Escaping literal % or _

What if you actually want to find a value containing a literal percent sign or underscore? Use a backslash to escape, or define your own with ESCAPE:

-- Find prices containing a percent sign in their text
SELECT note FROM sale WHERE note LIKE '%\%%';
-- Looking for "%". The middle \% is a literal percent sign.

-- Underscores in product codes (e.g., "A_B")
SELECT code FROM product WHERE code LIKE 'A\_B';

Putting It Together, A Worked Query

Question: "From the film catalog, list the 10 longest family-friendly films, rated G, PG, or PG-13, with length between 90 and 180 minutes and a title containing 'LOVE', showing title, length, and rating, sorted by length descending and title ascending."

Step 1, plain SELECT

SELECT title, length, rating FROM film;

Step 2, filter by rating with IN, and by range with BETWEEN

SELECT title, length, rating
FROM film
WHERE rating IN ('G', 'PG', 'PG-13')
  AND   length BETWEEN 90 AND 180;

Step 3, also match a title pattern with LIKE

SELECT title, length, rating
FROM film
WHERE rating IN ('G', 'PG', 'PG-13')
  AND   length BETWEEN 90 AND 180
  AND   title LIKE '%LOVE%';

Step 4, sort longest first, then alphabetical for ties

SELECT title, length, rating
FROM film
WHERE rating IN ('G', 'PG', 'PG-13')
  AND   length BETWEEN 90 AND 180
  AND   title LIKE '%LOVE%'
ORDER BY length DESC, title ASC;

Step 5, keep only the top 10

SELECT title, length, rating
FROM film
WHERE rating IN ('G', 'PG', 'PG-13')
  AND   length BETWEEN 90 AND 180
  AND   title LIKE '%LOVE%'
ORDER BY length DESC, title ASC
LIMIT 10;

That's the full toolkit at work: IN, BETWEEN, LIKE in the filter; ORDER BY for sorting; LIMIT to cap.

Order of clauses in MySQL: SELECT ... FROM ... WHERE ... ORDER BY ... LIMIT .... You can't reorder these. ORDER BY always comes before LIMIT.

Recap, what we covered

  • ORDER BY col sorts the result. Default is ASC; use DESC for descending.
  • You can sort by multiple columns; later columns break ties from earlier ones.
  • You can sort by an expression, a function call, or a column alias from SELECT.
  • LIMIT n caps the result at n rows. Always pair with ORDER BY when order matters.
  • LIMIT n OFFSET m (or LIMIT m, n) skips m rows then returns n, the basis of pagination.
  • BETWEEN a AND b for inclusive ranges. IN (...) for "any of these". IS NULL / IS NOT NULL for missing values.
  • LIKE matches patterns with % (zero or more chars) and _ (exactly one char).
  • MySQL LIKE is case-insensitive by default; use BINARY for strict case matching.
  • Escape literal % or _ with a backslash, or with a custom ESCAPE char.
  • Clause order is fixed: SELECT ... FROM ... WHERE ... ORDER BY ... LIMIT ....
