CREATE TABLE, The Basic Shape

From Lecture 2 you know how to brainstorm columns and pick types. Now we put them into a real table definition.

CREATE TABLE student (
  student_id   INT,
  name         VARCHAR(100),
  email        VARCHAR(120),
  date_of_birth DATE,
  major        VARCHAR(60)
);

Anatomy of the statement

  • CREATE TABLE followed by the table name.
  • Inside parentheses, a comma-separated list of columns.
  • Each column is name TYPE (and optionally constraints, which we'll add next).
  • The whole statement ends with a semicolon.
What we have so far: A table that structurally works, but it has no rules. Two students could have the same email, two students could share a student_id, names could be missing. The next slides fix that with constraints.

PRIMARY KEY, Single Column

A primary key uniquely identifies each row. We declare it on the column we want to be the row's identifier.

CREATE TABLE student (
  student_id INT PRIMARY KEY,
  name       VARCHAR(100),
  email      VARCHAR(120)
);

What PRIMARY KEY guarantees

  • Every row has a unique value for that column.
  • That value is never NULL.
  • The database refuses any INSERT that would break either rule.

Equivalent table-level form

CREATE TABLE student (
  student_id INT,
  name       VARCHAR(100),
  email      VARCHAR(120),
  PRIMARY KEY (student_id)
);

Both forms produce the same result. The table-level form is required when the key spans multiple columns (next slide).

Compound PRIMARY KEY

Sometimes no single column is unique, but a combination of columns is.

Enrollment table: A student appears in many rows (one per course they take). A course has many students. But the pair (student_id, course_id) is unique, that's our compound key. 
CREATE TABLE enrollment (
  student_id INT,
  course_id  VARCHAR(10),
  grade      VARCHAR(2),
  PRIMARY KEY (student_id, course_id)
);

Student 101 appears twice and course STAT301 appears twice, both fine. The pair never repeats.

FOREIGN KEY, Linking Tables

A foreign key says: "the value in this column must match a primary key in another table". This is how related tables stay consistent.

Customer
  • 🔑 customer_id (PK)
  • name
  • email
Order
  • 🔑 order_id (PK)
  • ↗ customer_id (FK)
  • order_date
  • total
CREATE TABLE customer (
  customer_id INT PRIMARY KEY,
  name        VARCHAR(100),
  email       VARCHAR(120)
);

CREATE TABLE `order` (
  order_id    INT PRIMARY KEY,
  customer_id INT,
  order_date  DATE,
  total       DECIMAL(10, 2),
  FOREIGN KEY (customer_id) REFERENCES customer(customer_id)
);
What MySQL refuses now: inserting an order with a customer_id that doesn't exist in customer. The foreign key turns "valid reference" into a database-enforced rule, not a hope.

A note on the Enrollment table

Compound keys and foreign keys often appear together. The enrollment table from the previous slide both has a compound PK and references two other tables:

CREATE TABLE enrollment (
  student_id INT,
  course_id  VARCHAR(10),
  grade      VARCHAR(2),
  PRIMARY KEY (student_id, course_id),
  FOREIGN KEY (student_id) REFERENCES student(student_id),
  FOREIGN KEY (course_id)  REFERENCES course(course_id)
);

NOT NULL and UNIQUE

NOT NULL, the value is required

Add NOT NULL to a column to forbid NULLs. The database will reject any INSERT that doesn't provide a value (and that has no DEFAULT).

name VARCHAR(100) NOT NULL

UNIQUE, no duplicates

Add UNIQUE to forbid two rows from holding the same value in that column.

email VARCHAR(120) UNIQUE

UNIQUE vs PRIMARY KEY

  • Both forbid duplicates
  • PRIMARY KEY also forbids NULL
  • A table has at most one PRIMARY KEY
  • A table can have many UNIQUE columns

Combine them

A column can be both NOT NULL and UNIQUE, that gives you a non-null, no-duplicates field, almost like a secondary primary key.

email VARCHAR(120) NOT NULL UNIQUE

🧠 Quick Check

A column declared VARCHAR(50) NOT NULL UNIQUE can hold:

DEFAULT, CHECK, and ENUM

DEFAULT, a fallback value

If no value is given on INSERT, MySQL uses the default.

major      VARCHAR(60) DEFAULT 'Undeclared',
created_at TIMESTAMP   DEFAULT CURRENT_TIMESTAMP

CHECK, a rule the value must pass

gpa DECIMAL(3, 2) CHECK (gpa BETWEEN 0.00 AND 4.00)

Any insert with a GPA outside 0.00 ... 4.00 is rejected.

ENUM, pick from a fixed list

ENUM restricts a column to a small, fixed set of allowed values.

status ENUM('active', 'graduated', 'on_leave') DEFAULT 'active'

All together

CREATE TABLE student (
  student_id INT           PRIMARY KEY,
  name       VARCHAR(100)  NOT NULL,
  email      VARCHAR(120)  NOT NULL UNIQUE,
  major      VARCHAR(60)   DEFAULT 'Undeclared',
  gpa        DECIMAL(3, 2) CHECK (gpa BETWEEN 0.00 AND 4.00),
  status     ENUM('active', 'graduated', 'on_leave') DEFAULT 'active',
  created_at TIMESTAMP     DEFAULT CURRENT_TIMESTAMP
);

Read it like a contract: every row needs a name, every email is unique, GPA must be 0 to 4, status is one of three values, created_at fills itself in.

AUTO_INCREMENT, Automatic IDs

For an integer primary key, you usually don't want to invent the next ID by hand. AUTO_INCREMENT tells MySQL to do it for you.

CREATE TABLE book (
  book_id INT           PRIMARY KEY AUTO_INCREMENT,
  title   VARCHAR(200) NOT NULL
);

-- We don't supply book_id, MySQL assigns it
INSERT INTO book (title) VALUES ('The Pragmatic Programmer');
INSERT INTO book (title) VALUES ('Clean Code');
-- book_id becomes 1, 2, 3, ...

Notes on AUTO_INCREMENT

  • Only one column per table can be AUTO_INCREMENT, and it must be a key (usually PK).
  • You can still supply a value manually if you want; MySQL keeps going from there.
  • If a row is deleted, its ID is not automatically reused. Don't treat IDs as a row count.

ALTER TABLE, Changing Structure Later

Tables aren't carved in stone. ALTER TABLE lets you add, change, rename, or drop columns and constraints after the table exists.

-- Add a column
ALTER TABLE student ADD phone VARCHAR(20);

-- Change a column's type or constraints
ALTER TABLE student MODIFY phone VARCHAR(25) NOT NULL;

-- Rename a column (MySQL 8+)
ALTER TABLE student RENAME COLUMN phone TO mobile;

-- Drop a column
ALTER TABLE student DROP COLUMN mobile;

-- Add a constraint after the fact
ALTER TABLE student ADD CONSTRAINT uq_email UNIQUE (email);
Be careful with DROP COLUMN. It deletes all the data in that column, no undo.

INSERT, UPDATE, DELETE

Once a table exists, here's how you put data in, change it, and take it out.

INSERT, add a row

INSERT INTO student (name, email, date_of_birth, major)
VALUES ('Maya Hassan', 'maya@isrt.ac.bd', '2003-08-12', 'Statistics');

INSERT, multiple rows at once

INSERT INTO student (name, email)
VALUES
  ('Arif Rahman', 'arif@isrt.ac.bd'),
  ('Priya Das',   'priya@isrt.ac.bd');

UPDATE, change rows

UPDATE student
SET major = 'Data Science'
WHERE student_id = 101;

DELETE, remove rows

DELETE FROM student WHERE student_id = 101;
Always include a WHERE clause on UPDATE and DELETE, unless you really mean to change every row. DELETE FROM student; with no WHERE empties the entire table.

DROP TABLE vs TRUNCATE TABLE

Two commands that look similar but do very different things.

DROP TABLE

Deletes the entire table, structure and data. The table is gone, you'd have to CREATE TABLE it again.

DROP TABLE student;

TRUNCATE TABLE

Removes all rows, but keeps the table's columns and constraints. Resets AUTO_INCREMENT back to 1.

TRUNCATE TABLE student;

And how does DELETE compare?

CommandRemoves dataRemoves tableResets AUTO_INCREMENT
DELETE FROM t;Yes (all rows)NoNo
TRUNCATE TABLE t;Yes (all rows, fast)NoYes
DROP TABLE t;YesYesTable is gone
None of these have an undo button. In real systems, take a backup before any of them.

Recap, what we covered

  • CREATE TABLE defines columns and constraints together.
  • PRIMARY KEY uniquely identifies rows; compound PK uses two or more columns.
  • FOREIGN KEY enforces references between tables.
  • NOT NULL, UNIQUE, DEFAULT, CHECK, ENUM are how we tell the database what counts as valid data.
  • AUTO_INCREMENT hands out IDs automatically.
  • ALTER TABLE adds, modifies, renames, or drops columns and constraints later.
  • INSERT, UPDATE, DELETE work on rows. Always include WHERE on the latter two.
  • DROP removes the table entirely, TRUNCATE empties it but keeps the structure.
