🚀 Challenge: Top Spenders Above the Average

One report, built up in four steps. You'll combine a JOIN, aggregation, a scalar subquery, and a final sort, exactly the tools from Lectures 7, 8, and 9.

The Scenario

The store manager wants a "high-value customers" list. For each customer in the system, show their name and total spend, then keep only customers whose total spend is above the per-customer average. Sort by total spend, top first, and cap at 10 rows.

Tables in play

customer and payment. Foreign key: customer.customer_id ↔ payment.customer_id.

1Per-customer total spend (JOIN + GROUP BY)

Join customer with payment. For each customer, return customer_id, first_name, last_name, and total_spent (SUM of amount, rounded to 2 decimals).

2Find the per-customer average spend (scalar subquery)

On its own, write a query that returns one number: the average per-customer total spend. (Hint: take the result of step 1, drop the customer columns, AVG the totals.) You'll use this number as a threshold in step 3.

3Filter step 1 with HAVING using the scalar subquery from step 2

Combine the two: keep only customers whose SUM(payment.amount) is greater than the scalar subquery's average. The condition lives in HAVING because it involves an aggregate.

4Sort and crop

Order the result by total_spent descending and keep only the top 10 rows. That's the finished report.

Compare with the suggested solution

When you've worked through all four steps, click below to see one possible final query.

-- Top 10 customers whose total spend is above the per-customer average
SELECT customer.customer_id,
       customer.first_name,
       customer.last_name,
       ROUND(SUM(payment.amount), 2) AS total_spent
FROM       sakila.customer
INNER JOIN sakila.payment
          ON customer.customer_id = payment.customer_id
GROUP BY customer.customer_id, customer.first_name, customer.last_name
HAVING SUM(payment.amount) > (
  SELECT AVG(total) FROM (
    SELECT SUM(amount) AS total
    FROM   sakila.payment
    GROUP BY customer_id
  ) AS per_cust
)
ORDER BY total_spent DESC
LIMIT 10;
How the pieces fit:
  • One INNER JOIN brings customer.first_name and customer.last_name alongside payment.amount.
  • GROUP BY rolls up to one row per customer; SUM(payment.amount) aggregates per group.
  • HAVING (not WHERE) filters whole groups, because the condition involves an aggregate.
  • The scalar subquery returns one number, the per-customer average spend, used as the HAVING threshold.
  • ORDER BY + LIMIT crop to the top 10 high-value customers.
