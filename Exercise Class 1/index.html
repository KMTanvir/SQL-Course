🚀 Challenge: Design a Small Clinic Database

Your final task. Design a small system for a family clinic, four tables that work together. Walk through each step in order. Your work is saved automatically.

The Scenario

A small clinic wants a database to track patients, doctors, the appointments between them, and the prescriptions written during each appointment. Your job is to design the tables and write the CREATE TABLE statements.

What we need to remember

  • Patient: name, date of birth, phone, gender, address.
  • Doctor: name, specialty, email, joined date.
  • Appointment: which patient, which doctor, when, status (scheduled / completed / cancelled), notes.
  • Prescription: which appointment, medicine name, dosage, duration in days.

1Brainstorm columns and types

For each of the four tables, list the columns you need and the type you'd pick for each. Don't worry about constraints yet, just types.

2Write CREATE TABLE for Patient and Doctor

Now write the actual SQL for the two simpler tables. Add primary keys, NOT NULL where required, UNIQUE on email.

3Write CREATE TABLE for Appointment

This one is trickier, the appointment links a patient and a doctor. You'll need two foreign keys. Use ENUM for status. Add a sensible DEFAULT for status.

4Write CREATE TABLE for Prescription

Each prescription belongs to one appointment. Add a CHECK that duration_days is positive. Decide whether dosage is text or numeric, justify in the textarea.

5Reveal the suggested design

When you're done with steps 1-4, click below to compare your approach with one possible solution. There's no single right answer; what matters is that your tables are well-typed, have appropriate constraints, and link correctly.

-- Possible solution. Yours may differ in column choices and that's fine.

CREATE TABLE patient (
  patient_id    INT PRIMARY KEY AUTO_INCREMENT,
  name          VARCHAR(100) NOT NULL,
  date_of_birth DATE NOT NULL,
  phone         VARCHAR(20),
  gender        ENUM('F', 'M', 'Other'),
  address       VARCHAR(200)
);

CREATE TABLE doctor (
  doctor_id   INT PRIMARY KEY AUTO_INCREMENT,
  name        VARCHAR(100) NOT NULL,
  specialty   VARCHAR(60) NOT NULL,
  email       VARCHAR(120) NOT NULL UNIQUE,
  joined_date DATE DEFAULT (CURRENT_DATE)
);

CREATE TABLE appointment (
  appointment_id INT PRIMARY KEY AUTO_INCREMENT,
  patient_id     INT NOT NULL,
  doctor_id      INT NOT NULL,
  appt_time      DATETIME NOT NULL,
  status         ENUM('scheduled', 'completed', 'cancelled') DEFAULT 'scheduled',
  notes          TEXT,
  FOREIGN KEY (patient_id) REFERENCES patient(patient_id),
  FOREIGN KEY (doctor_id)  REFERENCES doctor(doctor_id)
);

CREATE TABLE prescription (
  prescription_id INT PRIMARY KEY AUTO_INCREMENT,
  appointment_id  INT NOT NULL,
  medicine_name   VARCHAR(120) NOT NULL,
  dosage          VARCHAR(60) NOT NULL,    -- e.g., '500mg twice daily'
  duration_days   SMALLINT CHECK (duration_days > 0),
  FOREIGN KEY (appointment_id) REFERENCES appointment(appointment_id)
);
Notes on the choices:
  • gender uses ENUM for the small fixed list. Could also be CHAR(1) or VARCHAR(10).
  • dosage as VARCHAR because real-world dosages are messy text ("1 tablet, 3x daily"). A pure number would lose information.
  • appt_time is DATETIME because the user picks a wall-clock time, no timezone math needed for a single clinic.
  • The order of CREATE TABLE statements matters: parent tables first (Patient, Doctor) before tables that reference them (Appointment, then Prescription).
