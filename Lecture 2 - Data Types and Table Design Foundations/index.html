Designing a Table, Start with Brainstorming

Before writing CREATE TABLE, ask yourself a simple question: what do I need to store about this thing?

Scenario: We want a table to track students. List every fact we'd like to remember about each student. No SQL yet, just bullet points.

First brainstorm pass

  • name
  • email
  • phone
  • major
  • date of birth
  • year of admission
  • address

Then we ask the second question: what kind of value is each one? Is it text? Is it a number? A date? Could it be missing? The answer to those questions becomes our column types.

Character Types: CHAR vs VARCHAR

Both store text. The difference is in how MySQL stores them.

CHAR(n), fixed length

Always stores exactly n characters. Shorter values are padded with spaces.

  • Fast for fixed-width data
  • Wastes space when values are short
  • Good for: country codes (BD), gender flags (M, F), fixed IDs

VARCHAR(n), variable length

Stores up to n characters, only as much space as the value actually needs.

  • Saves space for varying lengths
  • Tiny per-row overhead to track length
  • Good for: names, emails, titles, addresses

Quick comparison

Stored valueCHAR(10)VARCHAR(10)
'BD''BD········' (10 chars)'BD' (2 chars + 1 length byte)
'Maya''Maya······' (10 chars)'Maya' (4 chars + 1)
'1234567890''1234567890' (10 chars)'1234567890' (10 + 1)

TEXT, when VARCHAR isn't enough

VARCHAR has a maximum (65,535 bytes per row, shared across all VARCHARs). For long content like blog posts or product descriptions, use TEXT.

Numeric Types

Numbers come in three flavors: integers, exact decimals, and approximate floating-point.

Integers (whole numbers)

TINYINT
Range -128 to 127 (or 0 to 255 unsigned)
Use for: small flags, age, ratings (1-5)
SMALLINT
Range about ±32,000
Use for: year offsets, small counts
INT
Range about ±2.1 billion
Use for: most IDs, counts, quantities
BIGINT
Range about ±9.2 quintillion
Use for: huge IDs, big counters

Exact decimal: DECIMAL(p, s)

DECIMAL(p, s) stores numbers exactly, where p = total digits and s = digits after the decimal point.

-- price stores numbers like 12345.67
DECIMAL(7, 2)   -- 5 digits before, 2 after

Floating point: FLOAT and DOUBLE

FLOAT and DOUBLE store numbers in approximate floating-point form. They cover huge ranges with few bytes, but the trade-off is rounding.

Temporal Types: DATE, DATETIME, TIMESTAMP, YEAR

Storing dates as strings is a classic beginner mistake. SQL has dedicated types so you can compare, sort, and do date arithmetic.

DATE
Just the date, no time
Format: '2026-04-29'
DATETIME
Date and time, no timezone
Format: '2026-04-29 14:30:00'
TIMESTAMP
Date and time, stored in UTC, converted on display
Use for: created_at, updated_at
YEAR
Just a four-digit year
Format: 2026
TIME
Just a time of day or duration
Format: '14:30:00'

DATETIME vs TIMESTAMP, the difference

DATETIME stores exactly what you give it. TIMESTAMP auto-converts to UTC on save and back to the server's local timezone on read, so the same row looks different in different timezones.

NULL: The Absence of a Value

NULL is SQL's special marker for "we don't know" or "doesn't apply". It is not the same as zero or empty string.

NULL means...

  • "Unknown", we don't have this data yet
  • "Not applicable", this field doesn't matter for this row
  • "Missing on purpose"

NULL is NOT...

  • The number 0
  • The empty string ''
  • The string 'NULL'
  • Equal to itself, NULL = NULL is unknown, not true

Why this matters

When you're designing a table, every nullable column is a question: "Could this value reasonably be missing for some rows?" Phone numbers, middle names, optional notes, all good candidates. Email addresses on a sign-up form, usually not.

We'll see in the next lecture how to force a column to never be NULL. For now, the important thing is to recognize NULL as a real, distinct value, not zero, not blank.

A First Taste of CREATE TABLE

Now that you can pick types, let's actually build a small table. We'll use just types for now, the full toolbox of constraints (PRIMARY KEY, FOREIGN KEY, NOT NULL, etc.) is the focus of Lecture 3.

The basic shape

CREATE TABLE table_name (
  column_1  TYPE,
  column_2  TYPE,
  ...
);

A real example, the Student table

CREATE TABLE student (
  student_id    INT,
  name          VARCHAR(100),
  email         VARCHAR(120),
  date_of_birth DATE,
  major         VARCHAR(60),
  gpa           DECIMAL(3, 2)
);

That's a working table. You could already insert and read rows from it. The catch: nothing stops two students from sharing the same student_id, and nothing forces name to be supplied. We fix that next class with constraints.

Useful First Commands

Once your table exists, here is the minimal toolkit to actually use it. We'll go deeper on each in later lectures.

See the structure of a table

DESCRIBE student;
-- or the longer form
SHOW COLUMNS FROM student;

MySQL prints each column with its type, whether it allows NULL, its default, etc. Great sanity check after a CREATE TABLE.

Put a row in

INSERT INTO student (student_id, name, email, date_of_birth, major, gpa)
VALUES (101, 'Maya Hassan', 'maya@isrt.ac.bd', '2003-08-12', 'Statistics', 3.85);

See what's in the table

SELECT * FROM student;

The asterisk * means "all columns". You'll learn richer queries later, this is the quickest way to confirm your insert worked.

List the tables in your database

SHOW TABLES;

Clean up your experiments

DROP TABLE student;

DROP TABLE removes the table entirely, both its structure and any data inside. While you're learning, this is how you start over with a fresh design.

Heads-up: DROP TABLE has no undo button. On the ISRT practice server it's fine, that's what learning is for. On a production database, check twice before pressing Enter.

Helpful built-in functions to know exist

You don't need to use these today, but knowing they're there pays off:

  • NOW(), current date and time, useful inside INSERT for a created_at column
  • CURDATE(), today's date
  • LENGTH(text), number of characters in a string
  • UPPER(text) / LOWER(text), change case
  • ROUND(number, n), round to n decimal places

Recap, What We Covered

  • Brainstorm columns first, list the facts you want to remember, then pick types.
  • CHAR(n) is fixed length (good for codes), VARCHAR(n) is variable length (default for most text), TEXT is for long content.
  • TINYINT / SMALLINT / INT / BIGINT for whole numbers, pick by the range you need.
  • DECIMAL(p, s) for exact numbers (money, GPA). FLOAT / DOUBLE for approximate scientific values.
  • DATE, DATETIME, TIMESTAMP, YEAR, TIME, never store dates as strings.
  • NULL means "unknown / not applicable". It is not zero, not empty string, not the literal text "NULL".
  • CREATE TABLE name (col TYPE, ...); is the basic table-building syntax. Constraints come next class.
  • You can DESCRIBE a table to see its structure, INSERT INTO to add a row, SELECT * to read it back, and DROP TABLE to start over.
